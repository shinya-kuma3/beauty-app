# 記事一覧の詳細検索

管理画面 `/admin` と公開側 `/articles/` に詳細検索を設置しています。公開側は静的ビルドへ取り込まれた公開済み記事だけが対象で、下書き・素材・審査メモは出力しません。

## 画面での使い方

キーワードは「セラミド 保湿 乾燥肌」のように、普通の言葉を空白で区切って入力します。「詳しい条件で探す」で含め方・含めない言葉・部位・タグ・年月・期間を指定し、「検索する」で適用します。

- キーワード：「すべて含む」または「いずれかを含む」。除外したい言葉は「含めないキーワード」へ入力します。特別な演算子を覚える必要はありません。
- タグ：「タグを選択」でモーダルを開き、登録済みタグをチェックします。タグ名で候補を探すこともできます。最大10個まで選べます。キャンセルは変更を破棄し、「選択を反映」で検索条件へ戻します。タグの含め方は「いずれかを含む」が画面の初期設定で、「すべて含む」にも切り替えられます。タグの除外はありません。
- 管理画面のタグ候補はDB上の記事に登録されたタグです。「一覧を更新」や記事の保存で更新します。公開側はビルドに含まれる公開記事のタグだけを表示します。
- 部位：肌・髪・爪・身体を複数選べます。選んだいずれかの部位に一致する記事を探します。
- 時期：年月、開始日・終了日。終了日を含みます。併用すると両方の条件に当てはまる期間を探します。年代・年の欄はありません。
- 管理画面は登録日・更新日・公開承認日を選べます。日時は日本時間で絞り込みます。公開承認日は管理者／編集者が承認した日時で、静的ビルド完了時刻とは異なります。
- 公開側は記事に表示されている更新日を基準に検索・並び替えます。
- 状態・キーワード・部位・タグ・時期の条件をすべて満たす記事を表示します。

キーワードと除外する言葉は合わせて最大12個、各入力欄500文字以内です。検索やリセットは編集中の本文を破棄しません。モーダルの閉じる操作・キャンセル・Escapeでは選択を確定しません。検索にはAIを呼びません。

公開側は検索条件をURLに保存でき、戻る・進むでも条件を復元します。JavaScriptが無効な場合も、公開記事の一覧は読めます。

## 管理画面のAPI

検索APIは管理者と利用中の編集者に限り、Cloudflare AccessのJWTを検証します。

GET `/api/admin/article-filters` は `tags`、`dates`、`time_zone` を返します。タグは重複を除き、内部のdraft以外の記事から取得します。

GET `/api/admin/articles` の検索パラメーター：

| 名前           | 指定                                                                                             |
| -------------- | ------------------------------------------------------------------------------------------------ |
| status         | pending_review（既定） / published / rejected / all。allにも内部のdraftは含めません              |
| q              | 空白区切りの普通のキーワード                                                                     |
| keyword_mode   | all（すべて含む） / any（いずれかを含む）。画面は必ず指定します                                  |
| exclude        | 空白区切りの、含めないキーワード                                                                 |
| scope          | content（タイトル・紹介文・本文・タグ。既定） / title / body（紹介文含む） / notes（信頼性メモ） |
| category       | skin / hair / nail / body。複数回指定可                                                          |
| tag / tag_mode | tagを複数回指定 / and・or。画面はorを初期設定とし明示送信します                                  |
| date_basis     | created（既定） / updated / published                                                            |
| month          | 2026-10など                                                                                      |
| from / to      | YYYY-MM-DD                                                                                       |
| sort           | newest（既定） / oldest。選択した日付基準でソート                                                |
| cursor         | 前の結果のnext_cursor。変更した検索条件には流用しない                                            |

旧クライアント向けにkeyword_mode未指定時の式の構文解析と、tagsのカンマ区切りは保持しています。現在の画面では使用しません。タグのnot、年代・年の指定はHTTP400になります。

1回50件を返し、次のページがある場合はnext_cursorが入ります。最初のページはtotalも返し、続きのページではtotalはnullです。同じ日時でもIDで順序を固定します。「続きを表示」には未適用のフォーム変更を混ぜません。

入力不正はHTTP400とerror.code、利用者向けのerror.messageを返します。検索語やタグはSQLパラメーターで渡します。%・_も文字として検索し、利用者の入力をSQLやFTS式として直接実行しません。

## 保存と反映

migration 0004_article_search.sqlのFTS5 trigram索引とタグの関係テーブルを引き続き使用します。本文・タイトル・タグ・信頼性メモの変更はDBトリガーで追従します。今回、新しいDB migrationやシークレットは不要です。

3文字以上の通常の語はtrigram索引を利用できます。2文字以下やワイルドカード記号そのものはLIKEの走査になるため、大量データでは時期・部位・タグも併用してください。

テストD1への索引の初回適用：

    npx wrangler d1 migrations apply beauty-content-test --remote --config wrangler.test.local.json

本番へのリリースでは本番D1に同じmigrationを先に適用してください。

編集者の管理では、利用中を緑、停止中を赤のチップとして表示し、利用停止後だけ削除できます。削除と利用再開は16px間隔で配置しています。
