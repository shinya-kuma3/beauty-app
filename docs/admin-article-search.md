# 管理画面の記事検索

対象は `/admin` の記事一覧です。管理者と利用中の編集者が使えます。検索APIもCloudflare AccessのJWTを検証し、公開サイトやGrok Botからは利用できません。

## 使い方

キーワードを入力して「検索する」を押します。「詳しい条件で探す」で部位、タグ、日付を追加できます。検索やリセットでは編集中の本文を破棄しません。記事を開き直す操作は従来どおり未保存の変更を確認します。

- 空白またはAND：すべて含む。例：保湿 AND セラミド
- OR：いずれか含む。例：保湿 OR セラミド
- NOT：除外。例：(保湿 OR セラミド) AND NOT 香料
- 優先順はNOT、AND、OR。括弧で順序を指定できます。
- 引用符で囲むと1つの語句になります。例："保湿の基本"、"AND"
- キーワードは最大500文字、12語、括弧の入れ子8段。日本語の2文字の語も検索できます。
- 部位は複数選択するといずれかに一致。タグはカンマ区切りで完全一致し、AND／OR／NOTを選べます（最大10個）。
- 状態、キーワード、部位、タグ、時期の各条件はANDで組み合わされます。
- 時期の基準は登録日・更新日・公開承認日。公開承認日は管理者／編集者が承認した日時で、静的サイトのビルド完了時刻ではありません。
- 年代（10年単位）、年、年月、開始日・終了日は日本時間で処理します。終了日は当日23:59:59.999まで含みます。併用するとそれぞれの期間の共通部分に絞られます。
- タグ候補は登録済みタグから最大500個。年代は保存済み記事の日付から作ります。新たに追加されたタグの候補は管理画面を再読み込みすると表示されます。

## API

GET /api/admin/article-filters は tags、dates（登録／更新／公開の最古・最新）、time_zone を返します。

GET /api/admin/articles の検索パラメーター：

| 名前                  | 指定                                                                                             |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| status                | pending_review（既定） / published / rejected / all。allにも内部のdraftは含めません              |
| q                     | 上記の検索式                                                                                     |
| scope                 | content（タイトル・紹介文・本文・タグ。既定） / title / body（紹介文含む） / notes（信頼性メモ） |
| category              | skin / hair / nail / body。複数回指定可                                                          |
| tags / tag_mode       | カンマ区切りタグ / and（既定）・or・not                                                          |
| date_basis            | created（既定） / updated / published                                                            |
| decade / year / month | 2020 / 2026 / 2026-10など                                                                        |
| from / to             | YYYY-MM-DD                                                                                       |
| sort                  | newest（既定） / oldest。選択した日付基準でソート                                                |
| cursor                | 前の結果のnext_cursor。変更した検索条件には流用しない                                            |

1回50件を返し、次のページがある場合はnext_cursorが入ります。最初のページはtotalも返します。続きのページではtotalはnullです。同じ日時でもIDを使って順序を固定します。offset方式からカーソル方式に変更しました。画面は適用済み条件を保持し、「続きを表示」に未適用のフォーム変更を混ぜません。

入力不正はHTTP400とerror.code、利用者向けのerror.messageを返します。検索式は構文解析したうえで値をSQLパラメーターとして渡します。SQLやFTSの演算子を直接実行しません。%・_も文字として検索します。

## 保存と反映

migration 0004_article_search.sqlでFTS5 trigram索引とタグの関係テーブルを作成し、既存の記事も索引に登録します。本文・タイトル・タグ・信頼性メモの変更はDBトリガーで追従します。日付と状態の並び替えにも索引を追加しました。

3文字以上の通常の語はtrigram索引を利用できます。2文字以下やワイルドカード記号そのものを検索する条件はLIKEの走査になるため、大量データでは時期・部位・タグも併用してください。検索にはAIを呼びません。

テストD1への適用例（ローカルのテスト専用設定を使用）：

    npx wrangler d1 migrations apply beauty-content-test --remote --config wrangler.test.local.json

本番は今回変更しません。本番へリリースする際は本番D1へ同じmigrationを先に適用してください。
